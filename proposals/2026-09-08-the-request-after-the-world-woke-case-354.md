# The Request After the World Woke — Pass 354

Status: PROPOSED / NON-CANON
Canon authority: NONE

## Premise

A field team arranged access to a specific survey instrument before leaving Puerto Bruma. The reservation window is later in the week. The provider also accepted the corresponding resource request.

The player then spends several in-world days elsewhere. Other NPCs travel, communicate, work and change plans. The session ends during an unrelated thread.

When the world is restored, the old instrument commitment still exists at the same causal moment as the restored NPC schedules and memories.

No NPC needs to repeat the original conversation to make the obligation true again.

## Why this case exists

This is a regression story for Pass 354 rather than new canon.

It tests a world where an apparently minor logistical promise can survive absence without becoming a quest flag recreated from dialogue.

It also creates a useful investigation pattern when an older save is loaded. A pre-V6 save can legitimately restore without persisted resource history. The fiction must not invent a reservation merely because an NPC remembers discussing one.

## Reduced version

The reduced version needs no AutoPTU battle.

The player returns to Puerto Bruma and learns that another job now wants the same instrument. The existing resource request and booking can be inspected together with current schedules and communications.

Possible outcomes include keeping the original window, voluntarily releasing it, negotiating another unit, or escalating to the existing allocation authority systems.

The story premise survives even if every later tactical encounter is omitted.

## Full encounter version

After the instrument is collected, the team must move it to a time-sensitive observation site. A wild encounter or environmental interruption threatens the arrival window.

The intended success condition is delivery of the functioning instrument before the observation window closes. Defeating every opponent is optional unless the situation itself makes combat unavoidable.

## Mechanical dependency map

Targeting / footprints / range / LoS: required for any tactical interruption using ordinary attacks or spatial threat selection. Current live evidence supports the audited ordinary targeting scope, but this does not certify every Move-specific targeting rule.

Base movement legality: required for ordinary grid travel during the tactical version. Current live evidence remains verified within the audited base scope.

Complete movement including push/pull/knockback/interception/forced movement: required if enemies can intercept the carrier, displace the carrier or instrument, or if rescue/carry interactions affect movement. Current evidence remains partial; those richer branches are gated.

Core calculations: required for ordinary deterministic battle arithmetic. Current audited core remains verified within its established scope.

Action economy / initiative: required if pickup, drop, protect, handoff or delivery actions occur inside tactical resolution. Ordinary action-budget primitives are verified, but each special cargo interaction needs an explicit contract.

Full turn/round lifecycle: required for a round-counted arrival deadline or round-start effects. Current evidence remains partial.

Full stateful damage pipeline: required if the carrier or instrument can take consequential combat damage. Current evidence remains partial.

Status lifecycle: required if persistent statuses can delay or disable the carrier. Current evidence remains partial.

Terrain / weather / hazards / zones / reactions: required only when those elements appear in the chosen encounter version. Each family remains gated by its own evidence.

Move-specific behavior: gated per Move.

Abilities: gated per Ability. Current Intimidate and Arena Trap work strengthens individual lifecycle seams but does not certify the full family.

Items: gated per Item.

Trainer Features / perks: gated per Feature.

AI legal-action infrastructure: ordinary audited infrastructure remains verified. Cargo-specific actions still require legal-action definitions before tactical AI can choose them.

AI tactical policy: blocking for a genuinely delivery-first encounter. The policy must understand preserving the carrier, reaching the destination and disengaging after the objective instead of assuming elimination is always optimal.

Minecraft / Cobblemon / Craftics adapter and playback: partial/blocking for end-to-end presentation of cargo ownership, objective completion and any new semantic tactical events.

## Fallback implementation

If complete movement, tactical cargo actions or objective-aware AI remain unavailable, resolve the interruption as ordinary travel plus an already-supported basic battle whose result affects delay rather than physical possession of the instrument.

The narrative fact remains the same: a previously persisted obligation led to a later time-sensitive delivery problem.

## Canon boundary

This proposal does not establish that this exact instrument, job or event occurred in Marea or Puerto Bruma canon.

Existing named people or locations may be used only as regression bindings if a later implementation test needs them. Promotion requires ordinary continuity review.
