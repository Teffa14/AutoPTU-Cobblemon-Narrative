# Marea / Sendero semantic-memory clock loop — Pass 261

Status: PROPOSED. Not canon-approved.

## Premise

The ecology layer should remember consequences for as long as their meaning requires, not for as long as an entity remains rendered.

A player can revisit the lower shelf after a field observation and find that some traces remain useful while other private correlations have expired. The result should feel like a world with memory instead of a set of spawn resets.

## Reduced playable loop

1. The player observes Fletchling activity at an existing Sendero location.
2. Ouros records the public observation and a short-lived private site-use correlation.
3. The visual day/night state may change without changing the retention clock.
4. The site-use correlation reaches its declared semantic horizon and closes. The field note remains.
5. A separate individual disturbance response remains active because its recovery condition has not yet been stable for long enough.
6. Server restart restores that active consequence rather than expiring it.
7. A fixture-only field marker becomes invalid through its own registry event. That link downgrades immediately even though little time may have elapsed.
8. A simulated world-clock rollback is detected. Automatic expiry suspends until a new clock epoch is reconciled.

The population remains twelve throughout.

## Player-facing effect

The player never sees clock epochs, internal source references, transaction IDs or registry policy IDs.

They may see consequences expressed diegetically:
- an old observation remains in field records;
- a previously disturbed individual is still harder to observe later;
- a marker record is reported lost and confidence drops;
- a location does not behave as though every server restart erased ecological history.

## Full version

A richer version can expose semantic memory through repeated fieldwork across several days, weather windows and NPC reports. Different consequences can resolve through different mechanisms: time, stable environmental conditions, institutional record changes or explicit world events.

The narrative premise does not require combat.

If the player actively follows a withdrawing Pokémon, dependencies become targeting/LoS, base movement, action economy/initiative, full turn/round lifecycle, AI legal-action infrastructure, AI tactical policy and adapter/playback. Interception or blocking adds complete movement. Terrain/weather/hazards/zones/reactions becomes required only when those mechanics actively change movement, observation or encounter resolution.

## Design value

This gives Ouros a clean way to support environmental storytelling across sessions without pinning every observation as a permanent actor. It also prevents a common MMO failure mode where server lifecycle becomes visible as world amnesia.

The same structure can later support migration, nesting cycles, recovery, conservation work, temporary resource ownership, social attachment and authoritative battle consequences without forcing those systems to share one timeout.

## Canon boundaries

No duration in the Pass 261 fixture is Fletchling biology canon.

No new NPC, institution, marker program, territory, nest, migration route or permanent individual is approved by this proposal.

The lower-shelf use is an implementation-grounding scenario only.

## Unresolved questions

- Which ecological consequences should progress only while the world server is running versus during real-world offline time?
- Which state classes require species-specific policies?
- How should players learn that a consequence ended when expiry itself is not directly observable?
- Should some horizons produce only internal cleanup while others create visible environmental change?
